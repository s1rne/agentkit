# Определение готовности

Все пункты своего уровня. Частичное выполнение — это `review`, но не `done`.

## Любая задача

- [ ] Приёмочные критерии выполнены или явно отмечены невыполненными с причиной
- [ ] Типы, линт, тесты зелёные
- [ ] Тесты написаны: CRUD и контракты — автором, **доменные расчёты — `qa-engineer`**
- [ ] `critic` дал вердикт `принято`
- [ ] Отчёт заполнен по `handoff-protocol`
- [ ] Документация обновлена, если поведение изменилось
- [ ] Найденное попутно вынесено в задачи, а не «поправлено заодно»

## Серверные задачи

- [ ] Мутации идемпотентны
- [ ] Изменение и событие в одной транзакции
- [ ] Есть тест изоляции данных на затронутые таблицы
- [ ] Нет обращений к БД мимо общей обёртки доступа

## Клиентские задачи

- [ ] Есть состояния: загрузка, пусто, ошибка
- [ ] Тексты через ключи локализации
- [ ] Клавиатурная навигация и видимый фокус работают
- [ ] Списки — курсорная пагинация

## `risk: high`

Деньги, права доступа, необратимые операции, миграции:

- [ ] **Человек посмотрел и подтвердил.** Вердикт `critic` этого не заменяет
- [ ] Доменные тесты написаны от требования, а не от реализации
- [ ] `security-auditor` прошёл, если затронуты права или персданные
- [ ] Миграция обратима или имеет обратную
- [ ] Проверено на реалистичном объёме данных, а не на трёх строках

## Чего «готово» не означает

Не означает «код написан». Не означает «у меня локально работает». Не означает «тесты позеленели после того, как я их поправил под код».
