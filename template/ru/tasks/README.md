# Система задач

Три уровня, как в инженерной команде. Всё файлами в git: доска в чужом SaaS не переживает потерю контекста и недоступна агенту.

```
Эпик (E-xx)      крупный блок, недели-месяцы      tasks/epics/
  └─ Фича (F-xxx)  законченная ценность, дни       tasks/features/
       └─ Задача (T-xxxx)  работа одного агента, часы  tasks/tasks/
```

Закрытые задачи переезжают в `tasks/done/`.

## Правила

1. **Задача берётся только со ссылкой на фичу**, фича — на эпик. Задача-сирота значит, что делают не то.
2. **У фичи проверяемые приёмочные критерии.** «Удобно» — не критерий.
3. **Статус во frontmatter**, доска генерируется из него. Руками доску не править.
4. **Готово ≠ написан код.** Навык `definition-of-done`.
5. **`in_progress` дольше суток = брошена** — вернуть в `todo`, причину в журнал.

## Статусы

`todo` · `blocked` (в `blocked_by` — чем) · `in_progress` (в `owner` — кем) · `review` · `done`

Формат файла задачи — навык `task-protocol`.

## Нумерация

Сквозная, не переиспользуется. Следующий свободный ID — в `BOARD.md`.
